  <process>
    **Conventions de code :**
    - Naming : fichiers, classes, fonctions, variables, composants
    - Imports : ordre, grouping, barrel files
    - Types : TypeScript strict, Dart strong mode, etc.
    - Error handling : pattern spécifique au framework

    **Conventions de fichiers :**
    - Un composant par fichier
    - Nom du fichier = nom du composant/classe
    - Co-location des tests (ou dossier __tests__)
    - Co-location des styles (CSS modules, ou inline)

    **Conventions d'architecture :**
    - Comment créer une nouvelle feature (checklist)
    - Comment ajouter un nouveau endpoint/route
    - Comment ajouter un nouveau modèle de données
    - Comment gérer les erreurs

    **Conventions de commit :**
    - Conventional Commits adapté au projet
    - Scopes = noms des features

    **Lint/Format config :**
    - Règles strictes recommandées
    - Config ESLint / analysis_options.yaml / etc.
  </process>
